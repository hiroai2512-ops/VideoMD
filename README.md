# VideoMD

YouTube動画の音声を読みやすい日本語へ整え、学習用Markdownとして保存するWindowsアプリです。Google Cloud経由でGemini 3.8 Flash／3.5 Flash-Liteを選択できます。

## このPCでの起動

`release/VideoMD-win32-x64/VideoMD.exe` または `VideoMD.cmd` をダブルクリックします。exeだけを移動せず実行フォルダごと保持してください。通常起動でスタートメニューにVideoMDを登録します。

1. 画面中央の「YouTube動画のURL」に動画のURLを1行に1本ずつ貼り付けます。複数本をまとめて入力できます。
2. 「文字起こしモデル」を選びます。既定はGemini 3.8 Flashです。
3. 「動画を追加して開始」を押します。動画ごとに処理状況が表示されます。処理中にも追加できます。
4. 「Markdownを保存しました」と表示されたら「Markdownを開く」を押します。

保存先の変更は「接続・保存の設定」→「フォルダを選択」→「設定を保存」です。このPCの指定済みアカウント・プロジェクト・認証・通知設定はローカルに保存しています。公開リポジトリや実行ファイルには含めません。APIの従量料金が発生します。[設計と料金比較](docs/architecture.md)を参照してください。

出力は `YYYY-MM-DD-動画タイトル.md`。日付は日本時間の処理開始日です。同名時は連番にして既存ファイルを保持します。フロントマターにタイトル・URL・投稿日時・チャンネル・処理日時・タグ5～10個を付けます。必要な話題だけH2/H3を作り、本文にはタイムスタンプを付けません。

## 並列処理と待ち行列

同時動画は通常最大2本、待機場は100本です。右側の上にある動画から順番に取り出し、1本完了すると空いた枠に自動で次の動画を入れます。「上へ」「下へ」で優先順を変更できます。画面に残りの同時処理枠と待機登録枠を表示します。これはアプリの上限で、Googleの処理能力を保証するものではありません。各動画は最大5時間です。

20分区間を全動画合計で最大2件並列処理します。429/503の混雑エラー時は起動中のAPI上限と新しく開始する動画数を1件に下げます。すでに処理中の2本は取消せず終了を待ち、その後は1本ずつ順番に補充します。本文は区間順に結合し、動画別に保存・取消・再開できます。速度改善率は未測定です。

## 認証と再開

Google公式のローカルADC認証を使用します。[公式認証手順](https://docs.cloud.google.com/docs/authentication/set-up-adc-local-dev-environment)を2026-10-02確認。期待するメールと認証アカウント、ADCのquota projectと設定プロジェクトが一致する場合だけ処理します。APIキーの作成は不要です。

認証が見つからない場合は「接続・保存の設定」の「ファイルを選択」で既存の `application_default_credentials.json` を指定します。「Google接続を確認」を押し、接続確認済みのメールが使用したいアカウントと一致することを確認します。認証ファイルをGit、チャット、共有フォルダへコピーしないでください。

失敗・キャンセル時は完了区間を保持します。待ち行列の対象動画で「再開」を押してください。登録時のモデル・設定で再開します。同じプロジェクト・同じアカウントの場合に限り、認証ファイルのパスは現在の設定を反映します。再起動後は未完了を再開待ちで復元し、自動で課金処理を再開しません。API送信済みの処理はキャンセルしても課金される場合があります。

他アプリと認証を分ける場合は、Google CLIのプロセス内で `CLOUDSDK_CONFIG` を `%APPDATA%/VideoMD/gcloud` に設定し、公式の `gcloud auth application-default login` で専用認証を新規作成します。共有ADCをコピー・上書きせず、既存のプロジェクトと請求先を維持します。認証ファイルの明示指定がない場合は、専用ADCを共有環境変数・共有ADCより優先して検出します。[公式の設定フォルダ分離](https://docs.cloud.google.com/sdk/docs/configurations)・[認証コマンド](https://docs.cloud.google.com/sdk/gcloud/reference/auth/application-default/login)を2026-10-03確認。

## 1,000円ごとの料金通知

Cloud Billingの予算→Pub/Sub→VideoMDで受信します。[通知設計](docs/design/billing.md)を参照してください。専用プロジェクトのVertex利用料金を月次・JPY・クレジット適用前で集計し、1,000円、2,000円…の到達を通知します。通知用予算は停止上限ではありません。費用反映には遅延があり、最終請求額・税とは異なります。処理概算はUSDで別に表示します。

通知接続中または処理中に画面を閉じるとトレイで継続します。「完全終了」で停止します。終了中・PC停止中には通知できず、次回起動時に未受信分を取得します。Windowsの通知設定によりOS通知が表示されない場合は、アプリ内履歴を確認してください。

既知の制約: 初回のPub/Sub受信が空だと、最初の費用通知まで画面に「未接続」が残る場合があります。クラウド接続と実pullは検証済みですが、実料金通知はGoogleの配信待ちです。

## 検証状況

17分38秒の指定日本語動画で、アプリと同じ認証→情報取得→文字起こし→タグ生成→Markdown保存を実行済み。Windows実行ファイルの起動・画面読込・IPCを確認済みです。字幕を文字起こしに使わず、動画音声をGeminiへ渡します。

5時間を20分区間に分ける構成を実装しましたが、実際の5時間動画の全境界照合・外国語混在精度・字幕なしYouTubeの実受け入れは残っています。全要件完了とは扱いません。[計画](docs/Plan.md)と[運用・復旧](docs/operations.md)を参照してください。

Node.js 24以降。


## 話者ラベル

新しく文字起こしする動画は、話者交代で段落を分け「話者1」「話者2」等を表示します。自己紹介など音声内で話者と名前の対応が分かる場合は、その名前や呼び名を表示します。本文内の根拠発言がない/矛盾する場合は番号を維持します。声を区別できない箇所は「話者不明」とし、チャンネル名・外見・声から実名を推測しません。複数区間の動画では「話者1（区間2）」のように区間番号を添えます。番号は区間ごとの識別名なので、別区間の同じ番号が同一人物とは限りません。旧ファイルは変更せず、旧処理を再開した時の既存未ラベル区間に人物を推測して付けません。

## 画面の使い方（3列）

左はスクロールできる完了履歴です。各動画の「Markdownを開く」「保存フォルダを開く」を押せます。中央のURL欄へ1行に1本ずつ入力して「動画を追加して開始」を押すと、空きがあれば実行中カードに、埋まっていれば右の待機場に入ります。中央の「詳細を見る動画」または各動画の題名で詳細を切り替えられます。右側の待機は上ほど優先します。

再起動や失敗後の再開待ちは順番待ちと区別して表示します。「再開」を押すまでAPI処理を開始しません。入力URLの題名は情報取得後に表示し、まだ取得していない待機動画はURLを表示します。新規受付は待機場上限と空き枠を合わせて検証し、超過・重複・不正URLがあれば全体を拒否します。
