# VideoMD データ・出力契約

2026-10-02。秘密情報と出力・通知履歴はGit管理対象外。

## Markdown

ファイル名: 日本時間の実行開始日による`YYYY-MM-DD-動画タイトル.md`。Windows禁則文字と予約名を安全化し、最大長を制限。同名時は`-2`等の連番で既存ファイルを保持する。YAMLはエスケープして生成し、取得値を文字列連結で無検証挿入しない。

フロントマター:

| フィールド | 内容 |
| --- | --- |
| title | 取得した元動画タイトル |
| source_url | 検証・正規化したYouTube動画URL |
| channel | 取得した投稿チャンネル名 |
| published_at | 取得した公開日時。文字起こし日とは別 |
| transcribed_at | 文字起こし実行開始日時（タイムゾーン付き） |
| tags | 内容に関連する重複のない文字列5～10個 |

本文は動画内の順序を保持した日本語の整文。外国語の発話を日本語に訳す。固有名詞・数値・否定・条件を保持し、聞き取れない箇所を創作しない。H2/H3は必要な話題だけ。発話中の明示的な見出しは優先する（外国語なら意味を保った日本語訳）。

## 途中保存

ジョブID、動画ID、取得メタデータ、実行開始日時、選択モデル、区間ID・開始終了秒、処理状態、結果、使用量をアプリのユーザーデータフォルダに保存。外部応答を信頼せず形式と長さを検証する。中断・再開で実行開始日時を変えて別ファイルにしない。

## 費用通知

通知元budget ID、期間開始、通貨、累計利用料金、データ受信日時、通知済みの1,000円単位の到達額を保存。

- JPYで値が非負・有限の場合のみ円で判定。異なるbudgetや期間、通貨のデータを混ぜない。
- 999円で未通知、1,000円で1回。1,000→3,100円では2,000と3,000の到達を両方記録。通知はまとめても履歴は残す。
- 同じ到達を再送・順序逆転・一時的な費用訂正・再起動で重複通知しない。新しい期間は別台帳。
- 公式費用データとトークンからの概算は別の値・通知種別で保存。請求確定額や税と同一だと説明しない。
- 外部応答やログに認証トークンを記録しない。アカウント情報とCloud Billing識別子は公開リポジトリに含めない。
