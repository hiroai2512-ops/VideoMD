# ローカル運用と復旧

2026-10-02。個人利用のWindowsローカルMVP。アプリサーバー・DBを常設しない。

- 設定・動画キュー・動画別ジョブ/API概算台帳・正式料金台帳はWindowsのAppData内のVideoMDに保存。設定は認証ファイルの参照先だけを保持し、トークンをコピー・保存しない。アカウント・請求先・費用は公開文書に載せない。
- 出力は設定フォルダへ保存。同名ファイルを保持し、一時ファイルからハードリンクで最終名を確保する。書き込み可能なNTFSローカルフォルダを選ぶ。エラー時は完了区間を保持する。
- バックアップは完全終了後にAppDataのVideoMDと出力フォルダを、本人だけがアクセスできる保存先へコピーする。認証ファイルを共有バックアップへ含めない。復元はアプリ終了後に元のフォルダへ戻し、Google接続と未完了ジョブを確認する。
- API失敗は画面の理由を確認し、認証・指定プロジェクト・API有効化・保存先を修正して再開。429/5xxは上限付き待機再試行。モデルや権限を自動変更しない。
- ロールバック条件: 起動不能、認証不一致でのAPI送信、保存データ破損、誤ったプロジェクト/通知対象。完全終了して旧版の実行フォルダへ戻す。出力とAppDataは削除しない。請求先解除やプロジェクト削除は復旧に含めない。
- 監視は処理状態・API概算・費用履歴。費用更新は遅延しPC停止中のOS通知は不可。日をまたいで受信できなければ予算とPub/Subの接続・権限を確認する。サブスクリプションの保持期間7日、31日非アクティブで期限切れの構成。長期休止後は接続を確認する。
- クラウド通知は専用プロジェクトに限定。停止上限・外部メール通知を追加しない。診断生成物はローカルruntime/exportsだけ。秘密・設定・台帳をGitへ送らない。

- 複数動画はAppData/VideoMD/jobs/<ID>に保存。旧job/usageは原本を残して取り込む。再起動後は対象動画の再開操作が必要。新しい待ち行列を旧版は読めないため、ロールバック後に旧単一ジョブだけを再実行すると重複課金の可能性がある。復旧時はキューと出力を照合する。
