# Plus 向け開発戦略の調査・採用記録

確認日: **2026-09-29（日本時間）**。技術仕様は更新されるため、モデル変更・設定エラー・プラン変更時に再確認する。

## GPT-6.1 Sol への更新

2026-10-02、ユーザーのモデル更新依頼に基づき、メイン・implementer・reviewerのモデルを `gpt-6.1-sol` に変更した。[公式Models資料](https://learn.chatgpt.com/docs/models?surface=app) でモデルIDとCodex向けの案内を確認。以下の2026-09-29の調査記録は当時の情報として保持し、現在の設定は `.codex/config.toml` と `.codex/agents/` を正本とする。

メイン・implementerはmedium、reviewerはhighを維持する。scout / lite_workerのLuna、advisorのAstra、既定子モデル、子数上限は変更しない。推論量と効果が世代間で同じとは仮定せず、使用量や開発速度の改善率は未測定とする。設定・文書の静的検証と、実際のモデル選択・起動の確認は分ける。

利用可否はアカウント・クライアント・展開状況に依存する。設定更新だけで実行中の会話のモデル変更や全役割の起動成功を保証しない。API課金や追加クレジット購入へ自動移行しない。

## 情報の優先順位

1. **現行の公式仕様**を優先する。対象が Codex か API か、Plus か Pro か、ローカルかクラウドかを必ず区別する。
2. 公式でも、大規模社内事例や API 用の最適化を Plus の運用保証とは扱わない。必要条件、課金、再現可能性を吟味する。
3. 同じ環境・主張で第三者情報が矛盾した場合、検証可能な一次体験を対象に、発信者の専門的実績と媒体内評価が高いものを優先する。
4. 同条件で比較できる情報は新しいものを優先する。新しい転載・感想だけで古い再現実験を覆さない。検索エンジンのクロール日を記事の更新日と混同しない。
5. 解消できない矛盾は両方を残し、ローカルの再現可能な確認を行う。根拠の薄い主張を設定の必須条件にしない。

## 発信者評価の基準

フォロワー数を X と Zenn と Quora で直接比較しない。知名度は正しさの代用ではなく、同程度の根拠を比較する補助指標とする。

採用候補について、再現証拠 E（0〜3）、専門実績 A（0〜3）、媒体内評価 P（0〜2）を記録する。これは本調査独自の評価であり、公的ランキングではない。

- E: 0=本文未確認または伝聞、1=具体的な一次経験、2=環境と手順あり、3=追試可能なコード・測定条件・結果あり。
- A: 0=実績未確認、1=本人の関連実践・継続発信あり、2=公開成果や保守経験を確認、3=該当技術の開発者・保守者として確認。
- P: 同じ媒体・近い技術分野で評価の高い著者群と比較できる場合だけ付与。通常の関連反応を確認=1、独立した専門家からの継続的評価も確認=2。比較母集団や反応を取得できなければ「不明」とする。
- X はフォロワーだけでなく元投稿の技術的具体性・専門家の引用、Zenn は技術記事への反応・継続した実装記事、Quora は当該話題の回答実績・根拠リンクを確認する。閲覧数だけは評価にしない。
- 更新の新しさと Plus への適用性を別欄で管理する。数値を推測で補完した合計ランキングは作らない。

## 採用しない情報

X・Quora は検証済みの採用資料なし。未取得の本文や自動生成された投稿要約を根拠にしない。
標準サブエージェントが利用できる場合、旧記事のSDK入れ子による擬似的な子の実装は採用しない。

## 矛盾をどう解決したか

| 論点 | 採用した判断 |
| --- | --- |
| 子に分ければ安くなる / 子が増えると消費が増える | 親の文脈量と全体の使用量を分ける。単独を基準に、必要な小数の子だけ使う |
| 高性能モデルを常駐させる / Plusで枠を温存する | 通常はSol、Astraは効率運用の判定A/Bと共通条件を満たす限定相談 |
| 毎回新会話 / 子を永続再利用 | 同じ作業は継続、無関係な作業や混乱した文脈だけ短い引き継ぎで切り替える |
| Lunaの推論量を最小化 / highを起点とする公式 | 実装はhigh、単純抽出だけlowを試す。実測の手戻りで調整する |
| 最新情報 / 著者の人気 | 現行仕様と適用条件を先に確認。同等の一次証拠なら実績・媒体内評価、同条件なら新しさを優先 |
| 細かな並列役割 / 調整コスト | 役割は5種類定義しても常駐させない。最大同時子2つ、孫への委譲なし |
| 巨大な AGENTS.md / 読込負荷 | 常時ルールと参照表を残し、従来の開発詳細・調査記録を必要時に読む |

## 未検証と今後の更新

同時子2、再試行2回、役割配分はこのリポジトリの初期判断で、OpenAI の推奨上限や実証済みの最適値ではない。
削減率と実行設定の反映は実際の開発で測定・確認する。設定ファイルの存在だけで効果や適用を保証しない。
新しい記事を採用するときは、URL・公開/更新日・確認日・プラン・クライアント・モデル・E/A/P・採否理由を追記し、古い設定を機械的に混在させない。
